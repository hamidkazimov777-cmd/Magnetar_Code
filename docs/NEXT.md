# Handoff — 0.2.0

Читай это, если подхватываешь работу за другой сессией.

## Как понять, что уже сделано

```bash
git log --oneline -20      # каждый блок = один коммит с префиксом fix(...)/feat(...)
npm run check              # format + lint + typecheck + test, должно быть зелёным
```

Ниже чеклист. Блок считается сделанным, только если есть коммит **и** тесты на него.

## Контекст

`magnetar-code` — CLI-агент + локальный монитор. Три пакета: `core` (движок:
провайдеры, agent loop, инструменты, права, сессии, память, демон), `cli`
(Ink TUI), `web` (Vite SPA, вшивается в CLI при сборке). Опубликован в npm,
версия 0.1.1. Полный аудит и архитектура — `docs/PLAN.md`.

**Инварианты, которые нельзя ломать.** Каждый защищает от конкретного бага,
который уже случался:

- Каждый tool call получает ответ, даже при ошибке — иначе следующий запрос к
  провайдеру невалиден.
- Пути резолвятся через `resolveInRoot` — наружу проекта не выходим.
- Демон не отдаёт CORS-заголовков и проверяет Origin; токен сравнивается
  константно. API-ключ не покидает Node-процесс.
- В agent loop есть потолок шагов, бюджет и отмена. Не убирать.
- `Session.list` сортируется по возрастающим меткам времени с добором по
  createdAt — иначе порядок плывёт на быстрых машинах.

## Правила работы

- `npm run check` зелёный перед каждым коммитом.
- Тесты на то, что чинишь. Баг без теста вернётся.
- Зависимостей не добавлять; в `core` их нет вовсе.
- Комментарии — только там, где неочевидно, и про «почему», не про «что».
- Один блок — один коммит.
- Выпуск: поднять `version` в `packages/cli/package.json`, коммит, тег
  `vX.Y.Z`, `git push origin main && git push origin vX.Y.Z`. Дальше
  workflow публикует сам. `repository.url` в package.json обязан совпадать
  с реальным адресом репозитория, иначе провенанс отвергает публикацию.
