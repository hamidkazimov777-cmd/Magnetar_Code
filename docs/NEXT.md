# Handoff

Универсальный промпт для любой модели, которая подхватывает работу над этим
проектом. Скопируй всё, что ниже разделителя, в новую сессию.

---

Ты продолжаешь работу над `magnetar-code` — это CLI-агент для кода плюс
локальный веб-монитор. Опубликован в npm, ставится как `npm i -g magnetar-code`.
Репозиторий: github.com/hamidkazimov777-cmd/Magnetar_Code

## Первым делом сориентируйся

```bash
git log --oneline -20      # что уже сделано; один блок работы = один коммит
npm run check              # format + lint + typecheck + test — должно быть зелёным
cat docs/PLAN.md           # исходный аудит и архитектура
```

Не верь описаниям — читай код. Если коммит говорит, что что-то сделано, а тест
на это отсутствует, считай, что не сделано.

## Что это

Три пакета в npm workspaces:

- `packages/core` (`@magnetar/core`, внутренний) — движок: провайдеры,
  agent loop, инструменты, права, сессии, память, HTTP-демон. Ноль
  runtime-зависимостей. Браузеро-безопасный подпуть — `@magnetar/core/commands`.
- `packages/cli` (`magnetar-code`, публикуется) — TUI на Ink и
  неинтерактивный режим `-p`. Ядро вбандливается через tsup.
- `packages/web` (`@magnetar/web`, внутренний) — монитор на Vite + React,
  собирается в статику и кладётся внутрь CLI при сборке.

Модель — это мозг, `core` — руки. Всё, что трогает машину, делает core;
модель только решает.

## Инварианты — не ломать

Каждый защищает от бага, который уже случался:

- Каждый tool call получает ответ, даже при ошибке, иначе следующий запрос к
  провайдеру невалиден.
- Пути резолвятся через `resolveInRoot` — наружу проекта не выходим.
- Демон слушает только loopback, требует токен (сравнение константное),
  отвергает чужой Origin и не отдаёт CORS-заголовков. API-ключ не покидает
  Node-процесс.
- В agent loop есть потолок шагов, бюджет и отмена. Не убирать.
- `Session.list` сортируется по строго возрастающим меткам с добором по
  `createdAt`, иначе порядок плывёт на быстрых машинах.
- Markdown в мониторе рендерится в React-элементы, без
  `dangerouslySetInnerHTML`. Вывод модели — недоверенный текст.
- Реестр команд живёт в `core`, CLI и веб читают один список. Они уже
  расходились однажды.

## Правила работы

- `npm run check` зелёный перед каждым коммитом.
- Баг чинится вместе с тестом на него, иначе он вернётся.
- Зависимостей не добавлять; в `core` их нет вовсе.
- Комментарии — только там, где неочевидно, и про «почему», не про «что».
- Один логический блок — один коммит с внятным описанием.
- Не переписывай то, о чём не просили.

## Выпуск новой версии

```bash
# поднять version в packages/cli/package.json, закоммитить, затем:
git push origin main
git tag vX.Y.Z && git push origin vX.Y.Z
```

Дальше GitHub Actions прогоняет проверки, собирает и публикует в npm с
provenance. `repository.url` в `packages/cli/package.json` обязан совпадать с
реальным адресом репозитория — иначе публикация отвергается с ошибкой
провенанса. Секрет `NPM_TOKEN` уже настроен.

Проверить результат:

```bash
npm view magnetar-code version
```

## Скриншоты для README

Обычный `chrome --headless --screenshot` тут не работает: страница держит
открытым SSE, и Chrome ждёт загрузку, которая не завершается. Снимать через
CDP: поднять `chrome --headless=new --remote-debugging-port=9222`, подключиться
по WebSocket, `Page.navigate`, подождать, `Page.captureScreenshot`. Демон для
съёмки поднимается так:

```bash
MAGNETAR_HOME=/tmp/shot/home MAGNETAR_NO_BROWSER=1 \
  node packages/cli/dist/cli.js web -C /путь/к/демо-проекту
```

Картинки лежат в `docs/images/`, на них ссылается README.
