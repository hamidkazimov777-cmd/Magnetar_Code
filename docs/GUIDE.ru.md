## 1. Что это такое

Magnetar — это помощник-программист, который живёт в терминале. Ты пишешь ему
задачу словами, а он сам читает файлы твоего проекта, ищет по коду, вносит
правки и запускает команды.

Важно понимать две части:

**Модель — это мозг.** Она думает и решает, что надо сделать. Ты подключаешь
любую: GPT, Claude, Gemini, DeepSeek, Kimi или даже локальную на своём
компьютере.

**Magnetar — это руки.** Сам он ничего не придумывает. Он даёт модели
инструменты (прочитать файл, найти код, записать, запустить команду) и
следит, чтобы она не натворила лишнего.

Отсюда простое правило: **чем сильнее модель, тем умнее агент**. На дешёвой
быстрой модели он будет переспрашивать очевидное. На сильной — сам разберётся.

## 2. Установка

Нужен Node.js версии 20 или новее.

```bash
node -v
```

Если написало `command not found` или число меньше 20 — зайди на
[nodejs.org](https://nodejs.org), скачай версию LTS и установи как обычную
программу. Потом открой терминал заново.

Ставим:

```bash
npm i -g magnetar-code
```

Проверяем:

```bash
magnetar --version
```

Если пишет `command not found` — закрой терминал и открой снова.

Если при установке была ошибка со словом `EACCES` — не хватает прав, повтори
ту же команду с `sudo` в начале.

**Обновление:**

```bash
npm i -g magnetar-code@latest
```

**Удаление:**

```bash
npm uninstall -g magnetar-code
```

## 3. Подключение модели

Magnetar не содержит внутри никаких ключей — ты подключаешь свой доступ к
любому сервису.

```bash
magnetar provider
```

Пройдёшь четыре шага:

**Шаг 1 — выбор сервиса.** Стрелками ↑ ↓ выбираешь из списка:

| Сервис            | Что это                                   |
| ----------------- | ----------------------------------------- |
| OpenRouter        | Доступ к сотням моделей через один ключ   |
| TokenRouter       | То же самое, другой поставщик             |
| Kimi (Moonshot)   | Модели Moonshot                           |
| OpenAI            | GPT напрямую                              |
| DeepSeek          | DeepSeek напрямую                         |
| Together          | Открытые модели                           |
| LM Studio (local) | Модель на твоём компьютере, ключ не нужен |
| Ollama (local)    | То же самое                               |
| Custom endpoint   | Любой свой адрес                          |

**Шаг 2 — API-ключ.** Вставляешь ключ от выбранного сервиса. Он уходит в
системное хранилище паролей (Keychain на Mac), а не в текстовый файл.

**Шаг 3 — модель.** Magnetar сам спросит у сервиса, какие модели доступны, и
покажет список. Начни печатать название, чтобы отфильтровать.

**Шаг 4 — модель для анализа проекта.** Отдельная модель, которая будет
изучать твой репозиторий и писать его память (об этом в разделе 8). Запускается
редко, поэтому сюда стоит поставить модель посильнее. Можно оставить ту же.

Позже поменять можно без повторного ввода ключа:

- `/model` — рабочая модель
- `/memory-model` — модель для анализа
- `/provider` — добавить ещё один сервис или переключиться

## 4. Первый запуск

Зайди в папку с проектом и запусти:

```bash
cd ~/мой-проект
magnetar
```

Увидишь заголовок с названием папки, сервисом, моделью и номером сессии.
Дальше просто пиши задачу словами:

```
посмотри, что это за проект, и опиши структуру
```

**Клавиши:**

| Клавиша           | Что делает                       |
| ----------------- | -------------------------------- |
| `Enter`           | Отправить                        |
| `\` затем `Enter` | Новая строка внутри сообщения    |
| `↑` `↓`           | История твоих сообщений          |
| `/`               | Открыть список команд            |
| `Esc`             | Остановить агента посреди работы |
| `Ctrl+C` дважды   | Выйти                            |

## 5. Как он работает внутри

Когда ты отправляешь задачу, начинается цикл:

1. Magnetar собирает **системный промпт**: какая у тебя ОС, в какой ты папке,
   какая ветка git, что лежит в корне проекта, и твои правила из `MAGNETAR.md`.
2. Отправляет модели твою задачу вместе со списком инструментов.
3. Модель отвечает: либо текстом, либо просьбой вызвать инструмент.
4. Magnetar выполняет инструмент (спросив тебя, если он опасный) и отдаёт
   результат модели.
5. Пункты 3–4 повторяются, пока модель не скажет «готово».

**Инструменты, которые есть у модели:**

| Инструмент    | Что делает                                  | Спрашивает? |
| ------------- | ------------------------------------------- | ----------- |
| `read_file`   | Читает файл                                 | Нет         |
| `list_dir`    | Показывает содержимое папки                 | Нет         |
| `glob`        | Ищет файлы по маске, например `src/**/*.ts` | Нет         |
| `grep`        | Ищет текст по регулярному выражению         | Нет         |
| `find_code`   | Умный поиск: «где реализована авторизация»  | Нет         |
| `edit_file`   | Меняет кусок файла                          | **Да**      |
| `write_file`  | Создаёт файл или перезаписывает целиком     | **Да**      |
| `run_command` | Запускает команду в терминале               | **Да**      |
| `todo_write`  | Ведёт план работ                            | Нет         |

**Защиты, которые работают всегда:**

- Агент не может выйти за пределы папки проекта. Попытка прочитать
  `../../.ssh/id_rsa` — отказ.
- Команда убивается по таймауту (2 минуты) и по нажатию `Esc`.
- Есть потолок шагов (25 по умолчанию) — агент не может крутиться вечно.
- Можно задать потолок трат в долларах.
- Слишком длинный диалог сжимается сам, до того как переполнится память модели.

## 6. Подтверждения — самое важное

Когда агент хочет изменить файл или запустить команду, он останавливается:

```
Run this command?
npm install express

y разрешить один раз · a всегда в этом проекте · n отказать
```

| Клавиша | Что происходит                                                         |
| ------- | ---------------------------------------------------------------------- |
| `y`     | Разрешить только сейчас                                                |
| `a`     | Больше не спрашивать про **эту же команду** в **этом** проекте         |
| `n`     | Отказать. Модели объяснят, что ты отказал, и она предложит другой путь |

Безобидные команды вроде `git status`, `ls`, `node -v` не спрашивают вообще —
иначе человек привыкает жать «да» не читая.

**Три режима** (меняются командой `/permissions`):

| Режим       | Поведение                                                 |
| ----------- | --------------------------------------------------------- |
| `ask`       | По умолчанию. Спрашивает про правки и команды             |
| `auto-edit` | Файлы правит молча, про команды спрашивает                |
| `yolo`      | Не спрашивает ни о чём. Только в папке, которой доверяешь |

## 7. Сквозной пример: приложение с нуля до релиза

Разберём реальный путь — делаем небольшой веб-сервис.

### Шаг 1. Создаём папку и запускаем

```bash
mkdir todo-api && cd todo-api && git init
magnetar
```

### Шаг 2. Просим спланировать, а не сразу писать

```
/plan сделай REST API для списка задач на Node.js и Express,
с хранением в SQLite, тестами и Dockerfile
```

Команда `/plan` — это заготовленный жёсткий промпт. Она заставляет модель
сначала подумать и показать план, а не бросаться писать код. Ты читаешь план и
поправляешь, если что-то не так.

### Шаг 3. Разрешаем реализовать

```
план хороший, делай
```

Дальше агент начнёт создавать файлы. Каждый раз будет спрашивать. Первые
несколько раз посмотри внимательно, что он пишет — потом можно на однотипные
команды отвечать `a`.

Если правок много и ты уже доверяешь — переключись:

```
/permissions
```

и выбери `auto-edit`. Файлы будет писать молча, но перед `npm install` всё
равно спросит.

### Шаг 4. Смотрим, что изменилось

```
/diff
```

Показывает все изменения в рабочей папке — как `git diff`, но не надо выходить
из сессии.

Если что-то пошло не туда:

```
/undo
```

Откатывает **только те файлы, которые менял агент** в этой сессии. Твою
собственную несохранённую работу он не трогает.

### Шаг 5. Пишем тесты

```
/test
```

Ещё один заготовленный промпт: он требует покрыть граничные случаи, ошибки и
пустой ввод, а не писать тесты, которые просто повторяют код.

### Шаг 6. Запускаем

```
/run npm test
```

Или просто попроси словами: «запусти тесты и почини, что упало». Агент запустит
сам и будет чинить, пока не станет зелёным.

### Шаг 7. Проверяем безопасность

```
/security
```

Заготовленный аудит: он ищет, откуда приходят недоверенные данные, куда они
попадают (shell, SQL, пути к файлам), проверяет авторизацию и хранение
секретов. И, что важно, ничего не меняет — только докладывает.

### Шаг 8. Приводим в порядок

```
/simplify
```

Ищет лишнее: дублирование, абстракции с одним вызовом, проверки состояний,
которых не бывает. И сразу правит.

```
/review
```

Смотрит на изменения как придирчивый коллега: сначала настоящие ошибки, потом
отдельно — что можно упростить.

### Шаг 9. Записываем память о проекте

```
/init
```

Модель-аналитик прочитает репозиторий и напишет `MAGNETAR.md` — как собирать,
как запускать тесты, где что лежит, какие есть подводные камни. Этот файл будет
попадать в каждую следующую сессию, и агенту больше не придётся заново
разбираться в проекте.

### Шаг 10. Коммитим

```
/commit
```

Читает изменения, разбивает на осмысленные коммиты и пишет сообщения, которые
объясняют «зачем», а не пересказывают дифф. Пушить сам не будет.

### Шаг 11. Документация и релиз

```
/docs
```

```
подготовь всё к публикации: README, лицензия, поле files в package.json
```

Всё, приложение готово.

## 8. Память проекта

Это то, что отличает агента, который знает твой проект, от того, кто каждый
раз начинает с нуля.

Память состоит из трёх слоёв, все попадают в системный промпт:

**1. Твои личные правила** — `~/.magnetar/MAGNETAR.md`. Действуют во всех
проектах. Например: «отвечай по-русски», «не пиши комментарии-очевидности».

**2. Правила проекта** — `MAGNETAR.md` в корне репозитория. Команды сборки,
соглашения, ловушки. Пишется командой `/init`, дальше можно править руками.
Лежит в git — значит, вся команда пользуется одной памятью.

**3. Отдельные факты** — папка `.magnetar/memory/`, по файлу на факт.

Записать факт на ходу, не прерывая работу:

```
/btw бэкенд деплоится только с ветки main
```

```
/remember в этом проекте всегда npm, не yarn
```

Модель при этом не вызывается — факт просто пишется в файл и попадает во все
будущие сессии. Посмотреть, что записано:

```
/memory
```

Удалить лишнее:

```
/forget deploy-target
```

Факты лежат обычными файлами, поэтому видны в `git diff` — всегда понятно,
чему научили агента.

## 9. Монитор в браузере

```bash
magnetar web
```

Откроется страница, показывающая **ту же сессию**, что и терминал. Это не
второй чат, а окно в текущую работу.

Что там есть:

- **Живой поток** — что агент пишет прямо сейчас.
- **Каждый вызов инструмента** — свёрнут в одну строку, разворачивается кликом.
  Диффы показаны сразу, зелёным и красным.
- **Дерево файлов** — изменённые помечены точкой.
- **План работ** — как агент его правит.
- **Память** — можно читать и редактировать прямо там.
- **Сессии** — переключаться и удалять.
- **Подтверждения** — те же три кнопки, что в терминале.

В поле ввода работают `/` (команды) и `@` (файлы проекта), можно перетащить
файл мышкой или прикрепить кнопкой `+`.

Важно: ключ в браузер не попадает. Запросы к модели делает процесс в терминале,
монитор получает только текст. Сервер слушает только твой компьютер и требует
токен, который лежит в адресной строке.

## 10. Все команды

Нажми `/` в сессии — откроется список с прокруткой. Начни печатать, чтобы
отфильтровать: поиск идёт по названию, сокращениям и описанию, поэтому `/key`
найдёт `/provider`.

Команды делятся на два вида. **Действия** выполняет сам Magnetar — они мгновенные
и бесплатные. **Промпт-макросы** — это заготовленные подробные задания, которые
отправляются модели.

### Сессия

| Команда     | Что делает                              | Пример                                                        |
| ----------- | --------------------------------------- | ------------------------------------------------------------- |
| `/new`      | Начать чистую сессию                    | Закончил задачу — начни новую, чтобы старый контекст не мешал |
| `/sessions` | Список прошлых сессий, переключиться    | Вернуться к вчерашней работе                                  |
| `/resume`   | То же самое                             |                                                               |
| `/clear`    | Стереть экран, сессию оставить          | Просто убрать визуальный мусор                                |
| `/compact`  | Сжать длинный диалог в пересказ         | Когда `/context` показывает, что заполнено                    |
| `/context`  | Насколько заполнена память модели       | Полоска и число токенов                                       |
| `/cost`     | Сколько потрачено за сессию             | `$0.0412`                                                     |
| `/export`   | Сохранить сессию в markdown             | Отчёт о том, что делал агент                                  |
| `/rename`   | Переименовать сессию                    | `/rename рефакторинг базы`                                    |
| `/fork`     | Скопировать сессию и продолжить в копии | Попробовать другой путь, не теряя текущий                     |
| `/status`   | Провайдер, модель, папка, режим         | Быстрая проверка                                              |

### Провайдер и модель

| Команда        | Что делает                    | Пример                             |
| -------------- | ----------------------------- | ---------------------------------- |
| `/provider`    | Добавить или сменить сервис   | Полный мастер с ключом             |
| `/login`       | То же самое                   |                                    |
| `/model`       | Сменить модель                | Взять посильнее для сложной задачи |
| `/models`      | Показать все доступные модели |                                    |
| `/logout`      | Удалить сохранённый ключ      |                                    |
| `/usage`       | Токены и траты сессии         |                                    |
| `/limits`      | Текущие потолки шагов и денег |                                    |
| `/temperature` | _Пока не поддерживается_      | Используется значение провайдера   |

### Работа с контекстом

| Команда           | Что делает                      | Пример                                             |
| ----------------- | ------------------------------- | -------------------------------------------------- |
| `/add <путь>`     | Прикрепить файл к разговору     | `/add src/db.ts`                                   |
| `/read <путь>`    | То же самое                     |                                                    |
| `/open <путь>`    | Показать файл прямо в терминале | `/open package.json`                               |
| `/search <текст>` | Найти по проекту                | `/search createUser`                               |
| `/tree`           | Показать дерево файлов          |                                                    |
| `/files`          | Что лежит в текущей папке       |                                                    |
| `/drop`           | _Заглушка_                      | Чтобы убрать старый контекст, используй `/compact` |

### Память

| Команда            | Что делает                                       | Пример                                        |
| ------------------ | ------------------------------------------------ | --------------------------------------------- |
| `/init`            | Проанализировать проект и написать `MAGNETAR.md` | Первое, что стоит сделать в новом репозитории |
| `/memory`          | Показать всю память, которая сейчас в работе     |                                               |
| `/memory-model`    | Выбрать модель для анализа проекта               | Поставь сюда сильную                          |
| `/analyst`         | То же самое                                      |                                               |
| `/remember <факт>` | Записать факт                                    | `/remember тесты запускаются через npm t`     |
| `/btw <заметка>`   | Записать на ходу, не прерывая задачу             | `/btw прод только с main`                     |
| `/forget <имя>`    | Удалить факт                                     | `/forget deploy-target`                       |
| `/rules`           | Путь к `MAGNETAR.md` проекта                     | Чтобы открыть в редакторе                     |

### Код и git

| Команда          | Что делает                          | Пример                              |
| ---------------- | ----------------------------------- | ----------------------------------- |
| `/diff`          | Что изменилось в рабочей папке      |                                     |
| `/undo`          | Откатить файлы, которые менял агент | Только через git, только его правки |
| `/branch`        | Показать ветку или переключиться    | `/branch feature/auth`              |
| `/build`         | Запустить `npm run build`           |                                     |
| `/lint`          | Запустить линтер                    |                                     |
| `/format`        | Запустить форматтер                 |                                     |
| `/run <команда>` | Выполнить что угодно                | `/run docker compose up -d`         |

### Промпт-макросы

Это главная ценность. Качество ответа задаёт промпт, а хороший промпт никто не
пишет заново каждый раз. Здесь они уже написаны.

| Команда     | Что просит у модели                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/review`   | Проверить изменения как придирчивый коллега: сначала настоящие ошибки с указанием файла и строки, потом отдельно — что упростить. Не хвалить и не пересказывать код |
| `/security` | Аудит по порядку: откуда приходят недоверенные данные → куда попадают → авторизация → секреты. Только реально достижимые дыры, не теоретические. Код не менять      |
| `/explain`  | Объяснить, как работает код, тому, кто будет его поддерживать: от точки входа по реальному потоку, с именами файлов                                                 |
| `/refactor` | Переписать, не меняя поведения. Сначала сказать что и зачем. Тесты должны остаться зелёными                                                                         |
| `/simplify` | Найти лишнюю сложность: дубли, абстракции с одним вызовом, проверки невозможных состояний. И сразу починить                                                         |
| `/docs`     | Написать документацию в стиле уже существующей в проекте                                                                                                            |
| `/fix`      | Воспроизвести ошибку, найти причину, а не симптом, починить, доказать запуском                                                                                      |
| `/plan`     | Спланировать работу до написания кода. Код не писать, пока не согласуешь                                                                                            |
| `/test`     | Написать тесты на то, что реально ломается: границы, пустой ввод, ошибки                                                                                            |
| `/commit`   | Прочитать дифф, разбить на осмысленные коммиты, объяснить «зачем». Не пушить                                                                                        |

К любому макросу можно дописать уточнение:

```
/security проверь особенно загрузку файлов
```

## 11. Запуск из скриптов и CI

Magnetar умеет отвечать один раз и выходить — без интерфейса.

**Простой вопрос:**

```bash
magnetar -p "какие роуты есть в этом приложении?"
```

**Скормить вывод другой команды:**

```bash
cat error.log | magnetar -p "почему это падает?"
```

```bash
npm test 2>&1 | magnetar -p "объясни, что упало"
```

**Ответ в виде JSON — для скриптов:**

```bash
magnetar -p "проверь типы" --output-format json
```

Вернёт объект с полями: ответ, id сессии, число шагов, потраченные токены и
стоимость.

**Разрешить правки без вопросов** (в скрипте некому нажать `y`):

```bash
magnetar -p "почини линтер" --permission-mode auto-edit
```

Если этого не сделать, инструмент, которому нужно подтверждение, получит отказ —
агент не будет висеть вечно.

## 12. Флаги командной строки

```
-p, --print <текст>      ответить один раз и выйти
    --output-format      text или json
-m, --model <id>         другая модель только на этот запуск
-C, --cwd <папка>        работать в другой папке
-c, --continue           продолжить последнюю сессию здесь
-r, --resume <id>        продолжить конкретную сессию
    --permission-mode    ask | auto-edit | yolo
    --max-steps <n>      остановиться после n шагов (по умолчанию 25)
    --max-cost <usd>     остановиться, когда прогон стоит столько
-h, --help               справка
-v, --version            версия
```

Подкоманды:

```bash
magnetar provider   # настроить доступ
magnetar web        # открыть монитор
magnetar doctor     # проверить настройки
```

## 13. Когда что-то не работает

**Первое, что стоит сделать:**

```bash
magnetar doctor
```

Проверит ключ, соединение с сервисом и наличие выбранной модели, и скажет, что
именно не так.

| Проблема                       | Что делать                                                       |
| ------------------------------ | ---------------------------------------------------------------- |
| `command not found: magnetar`  | Закрой терминал и открой заново. Не помогло — переустанови       |
| `No provider configured`       | Запусти `magnetar provider`                                      |
| `401` при запросе              | Ключ неверный или истёк. `/provider` заново                      |
| `404` при запросе              | Неправильный адрес сервиса — обычно он должен кончаться на `/v1` |
| Агент задаёт очевидные вопросы | Слабая модель. Смени через `/model`                              |
| Агент не находит нужный файл   | Скажи `/init` — он запишет память проекта                        |
| Диалог стал медленным          | `/compact`                                                       |
| Агент застрял                  | `Esc`, потом переформулируй задачу                               |

**Где что лежит:**

| Путь                         | Что это                              |
| ---------------------------- | ------------------------------------ |
| `~/.magnetar/config.json`    | Настройки, сервисы. Ключей здесь нет |
| Keychain системы             | Сами API-ключи                       |
| `~/.magnetar/projects/`      | История сессий, по папке на проект   |
| `~/.magnetar/MAGNETAR.md`    | Твои правила для всех проектов       |
| `MAGNETAR.md` в проекте      | Правила этого проекта                |
| `.magnetar/memory/`          | Факты о проекте                      |
| `.magnetar/permissions.json` | Команды, которым ты сказал «всегда»  |
| `.magnetar/index.json`       | Кэш поиска. Можно удалять            |
