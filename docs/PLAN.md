# Magnetar Code — CLI + Web-монитор. План доведения до публичного релиза

**Дата:** 2026-09-03 · **Автор ревизии:** Claude (после Gemini Pro 3.1)
**Объекты:** `/magnetar-cli` (637 строк, blessed), `/Magnetar-Web-UI` (Next 16, ~950 строк)

---

## 0. TL;DR

Что есть сейчас — рабочий прототип на один вечер: один файл `index.js` с TUI на `blessed`,
агент-цикл с 4 инструментами и Next-чат, который читает ключ из конфига CLI. Идея верная,
реализация — нет: ключ утекает в браузер, агент-цикл без ограничителей, ререндер O(n²),
`/web` перестанет работать сразу после `npm i -g`, а веб — это чат, а не «монитор».

Что предлагаю: не чинить точечно, а **вынести общее ядро в пакет и связать CLI и Web
локальным демоном**. Тогда ключи никогда не покидают Node-процесс, веб видит те же сессии
и тот же живой агент-стрим, а не свою параллельную вселенную.

Целевая установка для пользователя:

```bash
npm i -g magnetar-code   # или npx magnetar-code
magnetar                 # TUI в текущей папке
magnetar web             # тот же контекст в браузере
```

## 1. Аудит: что конкретно сломано

### 1.1 CLI (`magnetar-cli/index.js`)

**Безопасность**

1. `~/.magnetar/cli-config.json` пишется без `chmod 600` — API-ключ читает любой процесс пользователя.
2. `executeTool('run_terminal_command')` → `exec()` без таймаута, без `maxBuffer`, без ограничения по рабочей директории. Команда `npm run dev` подвесит CLI навсегда; `cat большой.log` — уронит.
3. Апрув только Y/N, без «always allow» и без allowlist безопасных команд (`ls`, `git status`) — на практике пользователь начнёт жать Y вслепую, и защита превращается в ритуал.
4. `read_file` не ограничивает размер — один `package-lock.json` (284 КБ) убивает контекст и кошелёк.

**Надёжность** 5. `runInference()` рекурсивно вызывает себя после tool-calls **без лимита шагов** — модель может крутиться бесконечно, счётчик тикает. 6. `config.messages` растёт вечно: нет обрезки/суммаризации → в какой-то момент провайдер отдаёт 400 и сессия мертва. 7. Во время стрима `Esc`/`Ctrl+C` = `process.exit(0)`. Нет отмены генерации, только убийство процесса. 8. `logBox.setContent(baseContent + marked(reply))` на **каждом токене** перерисовывает весь Markdown всей истории — квадратичная сложность, заметные лаги уже на 200 строках. 9. `/provider` уничтожает экран и требует перезапуска процесса (`magnetar provider`) — это костыль вокруг конфликта клавиатуры blessed/inquirer. 10. `/web` хардкодит `path.join(__dirname, '..', 'Magnetar-Web-UI')` и `npm run dev`. После глобальной установки папки-соседа нет → команда мертва. Плюс `spawn` не убивается при выходе — остаётся зомби-сервер на 3000.

**Полнота** 11. Шапка обещает `/help` — команды `/help` нет. 12. Нет: `/model`, `/init`, `/memory`, `/cost`, `/compact`, `/resume`, `/diff`, `/undo`, `/add`, `/tools`, `/permissions`, `/config`, `/doctor`, `/export`. 13. Нет неинтерактивного режима (`magnetar -p "..."`), нет чтения stdin — CLI нельзя вставить в скрипт или CI. 14. Нет `--help`/`--version` (версия захардкожена строкой `'1.1.0'` при `package.json: 1.0.0`). 15. Нет учёта токенов и стоимости, нет `usage` из ответа. 16. Многострочный ввод не работает (`blessed.textbox`, height: 1). 17. Сессии — плоские файлы без заголовка/даты/превью; список показывает `session-2026-09-03T...` — нечитаемо. 18. Нет `MAGNETAR.md`/памяти проекта, нет системного промпта вообще (модель не знает ни ОС, ни cwd, ни правил).

**Инженерия** 19. `test-*.js` (5 файлов) — мусорные ручные скрипты, попадут в npm-пакет (нет `files`/`.npmignore`). 20. `package.json`: пустые `author`/`description`, `license: ISC`, нет `repository`, `engines`, `keywords`. 21. `node-fetch@2` при Node 24 (есть глобальный `fetch`), `chalk@4`, `inquirer@8` — legacy CJS-набор. 22. Нет типов, линта, тестов, CI.

### 1.2 Web UI (`Magnetar-Web-UI`)

**Безопасность — критично** 23. `GET /api/config` отдаёт в браузер **весь конфиг вместе с `apiKey`**, без проверки `Origin` и без токена. Пока dev-сервер поднят, любая вкладка на любом сайте может сделать `fetch('http://localhost:3000/api/config')` и забрать ключ. Это не теоретическая дыра. 24. `POST /api/config` перезаписывает конфиг CLI без всякой проверки — тем же способом ключ можно подменить на свой прокси. 25. `OpenAICompatibleProvider` ходит к провайдеру **из браузера**: ключ лежит в `localStorage`, виден в DevTools/Network, и половина провайдеров отвалится по CORS.

**Функционально** 26. Это чат, а не монитор: сайдбар с папками — заглушка (`Magnetar`, `project LUMINA` захардкожены), файлового дерева нет, сессий CLI не видно, tool-calls и diff не отображаются, агента в вебе нет вообще. 27. `chat-store` не персистится — F5 стирает диалог. Сессии CLI (`~/.magnetar/sessions/`) веб не читает. 28. Нет рендера Markdown и подсветки кода — при том, что в CLI это уже сделано. 29. `syncWithLocalCLI` односторонний, `id = provider.name`, при переименовании плодит дубли; обновление существующего провайдера не делается вообще. 30. `fetchModels` требует `data.data` — падает на DeepSeek/Ollama/прокси, хотя CLI парсит три формата корректно. Логика разъехалась между реализациями. 31. `ChatContainer` собирает `requestMessages` из `messages` + временного сообщения — при быстрых отправках гонка со стором.

**Дизайн** 32. Стили — дефолтный нейтральный shadcn, `oklch(...)` серые из шаблона. Ни идентичности, ни пиксельности. Логотип — единственный брендовый элемент.

### 1.3 Главная архитектурная проблема

Одна и та же логика (провайдеры, стрим, парсинг моделей, сессии) написана **трижды**:
в Tauri-приложении Magnetar, в CLI и в Web UI — и уже разъехалась (см. п. 30).
Любая новая фича стоит ×3 и ломается в двух местах из трёх.

## 2. Целевая архитектура

```
magnetar-code/                       ← публичный репозиторий, npm-workspaces
├─ packages/core/                    @magnetar/core — вся логика, ноль UI
│   ├─ config/     профили провайдеров, пресеты, keychain
│   ├─ providers/  OpenAI-совместимый клиент, стрим, парсер /models
│   ├─ agent/      loop с лимитом шагов, бюджетом, отменой
│   ├─ tools/      fs/shell/grep/glob + песочница и таймауты
│   ├─ session/    JSONL-сессии, заголовки, resume, compact
│   ├─ memory/     MAGNETAR.md + ~/.magnetar/memory
│   └─ server/     локальный HTTP+WS демон (для веба)
├─ packages/cli/                     magnetar-code — Ink TUI + неинтерактивный режим
└─ packages/web/                     Next 16 «Монитор» — тонкий клиент к демону
```

**Ключевое решение — демон.** `magnetar web` поднимает в том же процессе HTTP+WebSocket
на `127.0.0.1:<случайный порт>` с одноразовым токеном в URL и открывает браузер на
`http://127.0.0.1:PORT/?t=<token>`. Все запросы к модели идут **из Node**, не из браузера.

Что это чинит разом: пп. 23, 24, 25 (ключ не покидает процесс, CORS не существует),
26, 27 (веб видит живые сессии и живой агент-стрим через WS), 29, 30 (один парсер),
и делает возможным апрув инструментов из браузера.

**Протокол демона** (WS, JSON-сообщения):

| Направление | Сообщение                                              | Смысл             |
| ----------- | ------------------------------------------------------ | ----------------- |
| →           | `session.list` / `session.open` / `session.new`        | сессии            |
| →           | `chat.send {text, attachments}`                        | отправка          |
| →           | `chat.cancel`                                          | отмена генерации  |
| →           | `tool.approve {id, decision: allow\|deny\|always}`     | апрув из браузера |
| ←           | `delta {text}` / `reasoning {text}`                    | стрим             |
| ←           | `tool.request {id, name, args, preview}`               | запрос апрува     |
| ←           | `tool.result {id, ok, output}` / `diff {path, patch}`  | результат         |
| ←           | `usage {in, out, costUsd}` / `done {reason}` / `error` | телеметрия        |

Тот же протокол потом переиспользует Tauri-приложение — и три реализации схлопнутся в одну.

**Ink вместо blessed.** 637 строк — не та величина, чтобы за неё держаться. Ink (React для
терминала) даёт нормальный инкрементальный рендер (лечит п. 8), фокус-менеджмент без
конфликтов (п. 9), готовые контролируемые инпуты с многострочностью (п. 16). На нём сделаны
все актуальные CLI-агенты. Blessed не развивается с 2015 года.

**Агент-цикл**

- Учёт `usage` + прайс-таблица → `/cost`.

**Инструменты** (расширить 4 → 9)

### Фаза 4 — Web-монитор (3–4 дня)

Не «второй чат», а **монитор рабочей папки**. Экран:

```
┌──────────────────────────────────────────────────────────────┐
│ ▚ MAGNETAR   ~/Magnetar · main*         deepseek-v4  $0.42   │
├───────────────┬──────────────────────────────┬───────────────┤
│ SESSIONS      │  поток агента                │  FILES        │
│ ▸ рефактор БД │  ▸ read_file src/db.rs       │  ▾ src/       │
│ ▸ фикс тестов │  ▸ edit_file  +12 −4  [diff] │    db.rs   ●  │
│ ▸ …           │  ▸ run_command npm test  ✓   │    lib.rs     │
│               │  ассистент: готово, …        │  ▾ docs/      │
│ MEMORY        │                              │               │
│ MAGNETAR.md   ├──────────────────────────────┤  TODO         │
│ 4 факта       │ > ввод                    ⏎  │  ☑ схема      │
└───────────────┴──────────────────────────────┴───────────────┘
```

Функции: живой стрим по WS, апрув инструментов кнопками (`Allow` / `Always` / `Deny`),
diff-вьюер на каждую правку, дерево файлов с пометкой изменённых, счётчик стоимости,
переключение сессий общее с CLI, панель памяти, Markdown + подсветка (`shiki`).

**Пиксельный дизайн-язык** (`docs/DESIGN_PIXEL.md` — отдельный документ фазы):

- Сетка 4 px, `border-radius: 0` везде, рамки 2 px сплошные.
- Тени только ступенчатые: `box-shadow: 4px 4px 0 var(--shadow)` — никаких blur.
- Шрифты: заголовки/лого — `Silkscreen` или `Departure Mono`; текст и код — `JetBrains Mono`.
- Палитра — чёрный/графит, **без фиолетового** (принцип из product-vision): `#0a0a0a` фон, `#141414` панели, `#2a2a2a` рамки, `#e8e8e8` текст, акцент `#f5a623` (янтарь), ok `#4ade80`, err `#ef4444`.
- `image-rendering: pixelated` для лого; иконки — свои 16×16 пиксельные спрайты, `lucide-react` выпиливаем (сейчас именно он даёт «типовой» вид).
- Курсор-каретка мигает блоком, состояния фокуса — инверсия, а не свечение.
- Опционально `prefers-reduced-motion`-совместимый scanline-оверлей 3 % — тумблером, по умолчанию выключен.
- Светлая тема — «бумажная»: `#f4f1ea` / чёрные рамки, тот же акцент.

Первым шагом фазы — статичный макет одного экрана, чтобы утвердить вид до логики.
